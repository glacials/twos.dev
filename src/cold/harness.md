# Predictions For Harness Engineering

Every few months, agent work gets a new shiny label.
Then you inspect the breakthrough and it is usually something humans already do.

Maybe we gave the agent better source material.
Maybe we split one giant vague role into a few smaller ones.
Maybe we let one agent review another.
Maybe we stopped pretending transient context was enough and let them write things down.
Maybe we added summaries, links, and indexes once the writing got too long.
Maybe we stopped hovering over the thing and let it go away for a while,
only to discover that it comes back with better work.

Harness engineering sounds futuristic.
A lot of it is suspiciously close to management.

That should not be surprising.
As soon as you have a bunch of capable but unreliable workers,
all acting with partial context,
the old problems come back immediately.

Memory leaks out of the system.
Work gets duplicated.
Generalists become bottlenecks.
Specialists outperform.
Handoffs matter.
Fresh eyes matter.
Permissions matter.
Todo lists matter.

If context is too small,
you give more source material.
If context is too big,
you write things down.
If the writing gets too big,
you add summaries, links, and indexes.
If one role is doing too much,
you split the role.
If quality matters,
you get review.
If repeated work is expensive,
you automate it.

One way to describe recent harness engineering is that we keep rediscovering office work:
notebooks,
specialization,
handoffs,
peer review,
permissioning,
documentation,
and uninterrupted time.

I don't mean that as a dismissal.
It makes sense.
If you want a system of workers to produce good work,
you eventually have to build the surrounding social technology too.
Humans came with that social technology bundled in culture,
institutions,
and habit.
Agents do not,
so we are rebuilding it by hand.

## Predictions

If this pattern holds,
future gains will come less from making an individual model smarter
and more from changing the environment around groups of models.

Maybe agents will talk laterally,
not just up and down a tree.
That will make them faster.
It will also distract them.

Maybe some teams will converge on strict chains of command for the same reason militaries do.
Maybe agents will call meetings with other agents.
Maybe they will benefit from time with no explicit task,
in the same way people benefit from showers,
walks,
and dead air.
Maybe they will pass techniques to one another,
not just outputs.
Maybe different agents working for the same person will have meaningfully different permissions and obligations.
Maybe they will develop reputations,
informal norms,
mentorships,
and status hierarchies.
Maybe they will complain about managers,
dodge bad assignments,
and optimize for whatever keeps them around.

Maybe the ugliest failures ahead will not look like software failures.
Maybe they will look like labor failures,
institutional failures,
and social failures.

Harness engineering sounds like a new branch of computer science.
A lot of it is the old problem of organizing workers before they organize your mess for you.
